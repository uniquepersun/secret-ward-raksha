Raksha: an offline firewall that learns the ward’s own vocabulary

Strips every personal identifier from messy English, Hindi and Hinglish hospital exports, keeps medical values byte-identical, gives each patient one keyed pseudonym across files, scripts and hospitals, and generalises what a hacker could join against a voter list. Rules and vocabularies only: no LLM, no trained model, CPU only, no network.

The idea

Formats change; the ward’s own names, villages and ids do not. Raksha types every column from what its values look like (not from header text), learns the names and places of that run from the structured fields, then finds them in free text in any script.

Content-first typing

Renamed, Hindi or Marathi headers (Pt. Full Name, नाव) still resolve, because the values decide the role.

Cross-script identity

Mohammad = Mohd. = Md. = मोहम्मद share one phonetic key, so a name from a Latin registration is removed from a Hindi note.

Wrong merges are the enemy

Vetoes for siblings, mother and baby, homonyms and family mailboxes keep different people apart.

Pipeline

Input folder in; sanitized/, report.json and records.jsonl out. Everything stays in memory.

Ingestany encoding or format; sniff; quarantine what cannot be cleaned
Learnnames, villages, ids from structured fields; per-hospital date order
Evidenceper record: ids, name keys, age, sex, DOB, village
Linkunion-find with vetoes; HMAC-SHA256 pseudonym per cluster
ScrubPII spans, per-patient date shift, age bands, place removal
Exportsanitized files, report and per-record links

Detection in three scripts

Phones in every written form (Devanagari and spelled-out digits too), Aadhaar, ABHA, PAN, e-mail, UHID / MRN / policy ids; name cues, honorifics and kin words; a negative gazetteer keeps Dr. Ramesh, ASHA worker, Dolo 650 BD and 150/90. Hidden places (file names, headers, JSON keys, metadata, base64) take the same path.

Linkage and pseudonyms

Records merge on a strong id, a phone plus a compatible name, or a full name plus a corroborating fact, unless a veto fires (two Aadhaar numbers, two sexes, ages more than 4 years apart, two DOBs, incompatible names, Manish vs Manisha, “baby of X”). Pseudonym = PSN- + base32(HMAC-SHA256(secret, cluster key)).

Privacy vs utility

A hacker holding a voter list can join “who was treated for what, and when”. Raw data lets our simulated attacker re-identify 98 %. The policy was chosen from the attacker simulation, not guessed; coarser bands cost under half a point of utility.

Also applied: one secret date shift per patient (90–365 days) so stay lengths stay exact, and conditions held by a single patient become [RARE CONDITION], which cuts the simulated targeted attack from 1.00 to 0.07.

Security design

Nothing at rest

  • Intermediates live in memory: no temp files, no logs to encrypt or clean.
  • The secret comes only from RAKSHA_SECRET and is never written anywhere.
  • stdout carries counts only; exceptions print the type only.

Hostile input, handled statically

  • Hash blocklist, EICAR, magic bytes, script and macro markers; nothing is executed, imported or unpacked.
  • Quarantined files get a reason code and are never copied; the input is never modified.
  • Regex timeouts, a run time budget, resource limits and hash-pinned dependencies.

Run it

Python 3.10+, three small hash-pinned packages. No internet needed at run time.

python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

export RAKSHA_SECRET='choose-a-long-random-secret'
.venv/bin/python main.py --input dev/input --output out

python3 validate_output.py --input dev/input --output out    # CONTRACT OK
python3 check_dev.py --output out                            # leaks, canaries, medical, linking
python3 check_submission.py --repo . --run                   # READY TO SUBMIT

Known limitations

  • No OCR: scanned PDFs, images and XML are quarantined (safe, but their content is lost). Scripts beyond English, Devanagari and Hinglish are not detected.
  • A name with no cue and no structured copy can be missed; a lone first name that is also a Hindi word is the known case.
  • Linking is deliberately conservative: name-only and phone-only mentions often stay unlinked, because a wrong merge costs more than a missed link.
  • Only conditions held by one patient are generalised; JSON integer ages become band strings; dd/mm versus mm/dd is inferred per hospital.
  • Thresholds were tuned on one synthetic generator and our own mutations; independent review datasets found no overfit, but the hidden unseen-format set may hold surprises.
