Raksha: an offline privacy firewall that learns the ward’s own vocabulary

Removes every personal identifier from messy English, Hindi and Hinglish hospital exports, keeps medical values byte-identical, gives each patient one keyed pseudonym across files, scripts and hospitals, and generalises what a hacker could join against a voter list. Deterministic rules: no LLM, no trained model, CPU only, no network.

1Pitch

The one idea that makes it robust to formats it has never seen: Raksha learns each run’s own names, villages and ids from the structured fields (column roles are typed from what the values look like, not from header text) and then finds them in free text in any script through a cross-script phonetic key (Mohammad = Mohd. = Md. = मोहम्मद).

3How each part works

Ingestion. Any encoding in, UTF-8 out. CSV keeps delimiter and ragged rows (headerless detected); JSON keeps structure and nested record lists; FHIR stays valid R4 (19/19 validate). Binary, malformed, deeply nested and XML files are quarantined with a reason code, never copied.
Linkage and pseudonyms. Merge on a strong id, a phone plus compatible name, or a full name plus a corroborating fact. Vetoes: two Aadhaar numbers, two sexes, ages >4 y apart, two DOBs, incompatible names, names differing only by a feminine ending (Manish / Manisha), “baby of X” with X. Pseudonym = PSN- + base32(HMAC-SHA256(secret, cluster key)), written inside the record.
Detection (3 scripts). Identifiers: Indian phones in every written form (Devanagari and spelled-out digits too), Aadhaar, ABHA, PAN, e-mail, masked numbers, UHID / MRN / policy ids. Names: cues (Name:, नाम:, honorifics, S/o, kin words), the learned lexicon by consonant skeleton, a rare-pair fallback. Meaning traps: a negative gazetteer plus context keep Dr. Ramesh, ASHA worker, Dolo 650 BD, 150/90; a relative named Ramesh is removed. Hidden places (file names, headers, JSON keys, metadata, base64) take the same path.
Privacy layer. One secret date shift per patient (90–365 days) in every date format, so stay lengths stay exact; 10-year age bands, 75+ top-code; village, house, landmark, PIN and tehsil removed, district kept; a condition held by one patient becomes [RARE CONDITION].

4USP: what a plain PII tool does not do

  • Content-first typing. Renamed, Hindi or Marathi headers (Pt. Full Name, नाव) resolve from the values.
  • Cross-script identity. Devanagari and Latin spellings share a phonetic key: a name learned from a Latin registration is removed from a Hindi note and the patient links across scripts.
  • Wrong merges are the enemy. Guards for siblings, mother and baby, homonyms, family mailboxes: 0 false merges on a 320-patient family stress set.
  • Measured, not guessed. An attacker simulation chose the generalisation policy; mutation and independent datasets test unseen formats.

6Security design

  • No data at rest: intermediates live in memory; no temp files or logs, so nothing to encrypt or clean.
  • Keys: secret only from RAKSHA_SECRET, never written; an empty key becomes a random per-run key.
  • PII-free logging: stdout carries counts only; exceptions print the type only.
  • Hostile input, static only: hash blocklist, EICAR, magic bytes, script and macro markers, hostile base64 removed, formulas neutralised; nothing is executed or unpacked.
  • Quarantine: reason code, never copied; input never modified; output paths confined.
  • Resilience: regex timeouts, a run time budget, resource limits, and hash-pinned dependencies.

7Known limitations (honest list)

  • No OCR: scanned PDFs, images and XML are quarantined (safe, content lost). Other scripts (for example Bengali) are not detected. A name with no cue and no structured copy can be missed (a lone first name that is also a Hindi word).
  • Linking is deliberately conservative: name-only and phone-only mentions often stay unlinked (recall), because a wrong merge costs more than a missed link.
  • Only conditions held by one patient are generalised; JSON integer ages become band strings; dd/mm versus mm/dd is inferred per hospital. Thresholds were tuned on one synthetic generator plus our own mutations; independent datasets showed no overfit, but the hidden set may hold surprises.
  • Free of external dependencies on data or models: no LLM, no pretrained model, no external dataset; three small hash-pinned Python packages only.
