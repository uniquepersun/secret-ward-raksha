Raksha: an offline firewall that learns the ward's own vocabulary

Track 3 · Secret Wards · Team: team-secret-ward · Members: Abhay · Repo: github.com/uniquepersun/secret-ward-raksha

1. In one paragraph

Raksha removes every personal identifier from messy English / Hindi / Hinglish hospital exports while leaving every medical value byte-identical, gives each patient one keyed pseudonym across files, scripts and hospitals, and generalises the quasi-identifiers an attacker would join against a voter list. It is deterministic rules and vocabularies, with no trained model. The one idea that makes it robust to formats it has never seen: it learns each run's own names, villages and ids from the structured fields (typed by what the values look like, not by header text) and then finds them in free text in any script through a cross-script phonetic key.

3. How each part works

  • Ingestion. UTF-8 / BOM / UTF-16 / cp1252, always written as UTF-8. CSV keeps delimiter, header and ragged rows; JSON keeps structure and value types; FHIR stays valid R4 (all 19 bundles validate with fhir.resources; fullUrls stay unique, references resolve). A .csv that is really JSON is sniffed. Binary, empty, malformed, 1,500-deep and XML files are quarantined with a reason code, never copied. Every file runs in its own try.
  • Detection. Identifiers: digit-run grouping rules for Indian phones in every written form (+91, 0-prefix, brackets, Devanagari digits, landlines), Aadhaar, ABHA, PAN, e-mail, masked Aadhaar, UHID / MRN / IPD / policy ids. URLs, UUIDs, ICD / LOINC codes and numeric ranges are protected. Names: cues (Name: / नाम:, honorifics, S/o D/o W/o, C/O <name> but not C/O fever, Shahid sahab, "called by"), the learned lexicon matched by a consonant skeleton (Mohammad = Mohd. = Md. = मोहम्मद), and a rare-pair fallback. Meaning traps: a negative gazetteer (drugs, diseases, eponyms, labs, units) plus context keep Dr. Ramesh, ASHA worker, Dolo 650 BD x 5 days, 1-0-1, 150/90, Parkinson's disease; a relative named Ramesh is removed. Hidden places (file names, headers, JSON keys, metadata, base64 attachments) take the same path.
  • Linkage and pseudonyms. Merge on a shared strong id, a phone plus compatible name, or one full name plus a corroborating fact (DOB, relative, village + age). Vetoes forbid two Aadhaar numbers, two sexes, ages >2 y apart, two DOBs or incompatible names in one cluster, so homonyms stay apart. Pseudonym = PSN- + base32(HMAC-SHA256(secret, cluster key)), written inside the cleaned record. A lone phone never creates an identity.
  • Privacy layer. One secret HMAC date shift (+-180 d) per patient across every date format, so stay lengths are exact; truthful 10-year age bands (75+ top-code); village, house, ward, mohalla, landmark, PIN and tehsil removed, district kept.
  • Security. All intermediates live in memory (no temp files, nothing to encrypt or clean); the secret is read from the environment only; exceptions print the type only; stdout carries counts only; quarantined files are never copied; the input is never modified.

4. USP: what a plain PII tool does not do

  • Content-first typing, not header trust. Renamed or Hindi headers (Pt. Full Name, Native Place, संपर्क नंबर) still resolve from the values; an unlabelled place column inside an address block becomes a village column.
  • Cross-script identity. Devanagari and Latin spellings share a phonetic key, so a name learned from a Latin registration is removed from a Hindi prescription, and the same patient links across scripts.
  • Measured, not guessed, privacy. The repo ships an attacker simulation; the generalisation policy was chosen from its numbers. A mutation harness (new names, headers, formats, labels, date styles) is our proxy for the unseen-format round.

6. Known limitations

  • No OCR: scanned PDFs / images and XML are quarantined (safe, but their content is lost); legacy-font Hindi is not decoded.
  • A name with no textual cue and absent from every structured field is found only by the rare-pair rule and can be missed.
  • Rare diagnoses are kept because they are medical values, so a targeted attack using a known rare condition still partly succeeds (simulated 0.21 of the raw 1.00).
  • dd/mm vs mm/dd is inferred per hospital from unambiguous dates; a hospital with none falls back to the global majority. JSON ages become band strings (a value-type change).
  • Thresholds were tuned on one synthetic generator plus our own mutations; the hidden unseen-format dataset may still contain surprises. No LLM, no pretrained model and no external dataset is used.
